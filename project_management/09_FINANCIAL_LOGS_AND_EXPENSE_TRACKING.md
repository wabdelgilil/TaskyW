# 09. وحدة السجل المالي والمصروفات وتسوية الحسابات (Financial Logs, Settlements & Invoice Tracking)

## 1. الرؤية والهدف (Vision & Purpose)
نظام مرن وخفيف جداً بنمط **Offline-First** لإدارة ومتابعة العمليات المالية اليومية، بدون تعقيدات حساب تكاليف المشاريع. يركز النظام حصرياً على:
1. **تتبع الفواتير المعلقة والمشتريات (Pending Invoices)** التي دُفعت ولم تُستلم فواتيرها بعد لتسهيل المطالبة بها.
2. **تسوية الحسابات والعهد المتبادلة (Cross-Account Settlements)**: معالجة المواقف الواقعية بدقة:
   - الدفع من أموالك الشخصية لمصاريف الشغل (مطالبة باسترداد عهدة / Reimbursement).
   - الدفع من حساب/عهدة الشغل لمصاريف شخصية (تسوية واجبة السداد للعمل / Due to Work).
   - التحويلات البنكية والنقدية بين المحافظ والحسابات المختلفة.

---

## 2. السيناريوهات وحالات الاستخدام المعتمدة (Core Use Cases)

### أ. إدارة ومتابعة الفواتير المعلقة (Pending Invoices & Receipts)
* تسجيل سريع لأي عملية دفع (سواء شغل أو شخصي) يكون استلام مستندها أو فاتورتها مؤجلاً:
  - تعيين الحالة تلقائياً أو يدوياً إلى **"بانتظار الفاتورة" (pending_invoice)** مع شارة تنبيه برتقالية واضحة.
  - قسم وفلتر مخصص يجمع لك كل العمليات التي ليس لها فواتير مستلمة لمتابعة البائعين أو الفنيين.
  - زر بضغطة واحدة لتحويل الحالة إلى **"مستلمة ومكتملة"** مع خيار إرفاق صورة الفاتورة فور استلامها.
  - تذكير ذكي دوري بعد عدد من الأيام ينبهك بالعمليات التي ما زالت بدون فاتورة.

### ب. تسوية الحسابات بين الشغل والشخصي (Work vs. Personal Settlements)
معالجة دقيقة للخلط المالي الذي يحدث يومياً:
1. **دفعت للشغل من جيبي الشخصي (Reimbursement Claim)**:
   - تمييز العملية بأنها مستحقة لي من الشغل (Company owes me).
   - تتبع حالتها: (معلقة للمطالبة pending / تمت التسوية واسترداد المبلغ settled).
2. **دفعت من حساب/عهدة الشغل لمصروف شخصي (Due to Company)**:
   - تمييز العملية بأنها مستحقة عليّ للشركة/العهدة (I owe company).
   - تتبع سدادها أو خصمها في التسوية القادمة.
3. **عداد التسوية الصافي (Net Balance Counter)**:
   - شريط ذكي في رأس الشاشة يوضح الموقف المالي بينك وبين الشغل:
     - 🟢 لك عند الشغل: +X ج.م (صافي مطلوب استرداده).
     - 🔴 عليك للشغل: -X ج.م (صافي واجب إعادته للعهدة).

### ج. حركة التحويلات بين الحسابات والمحافظ (Transfers)
* تسجيل حركة الأموال بسهولة:
  - من حساب بنكي (CIB، الأهلي...) إلى محفظة إلكترونية (فودافون كاش، إنستاباي...).
  - سحب كاش من البنك إلى المحفظة النقدية أو عهدة الشغل.
  - تحديد مصدر الدفع (rom_account) ومستلم الدفع (	o_account) من قائمة اختصارات جاهزة بضغطة زر.

### د. تصدير كشوف حساب التسويات (Settlement Export for Accounting)
* تصدير فوري بضغطة زر لملف Excel / CSV متوافق مع اللغة العربية يوضح:
  - جدول الفواتير المطلوب تسليمها للمحاسب.
  - كشف المبالغ المستحقة للاسترداد من العمل أو المبالغ الشخصية المدفوعة من عهدة الشركة لتسويتها في ثوانٍ.

## 3. المخطط البياني للبيانات (Database Schema - SQLite & Supabase)

### جدول العمليات المالية inancial_records:
`sql
CREATE TABLE IF NOT EXISTS financial_records (
    id TEXT PRIMARY KEY,                           -- UUID v4
    type TEXT NOT NULL,                             -- 'expense' | 'income' | 'transfer'
    amount REAL NOT NULL,                           -- القيمة الرقمية
    currency TEXT NOT NULL DEFAULT 'EGP',           -- العملة
    title TEXT NOT NULL,                            -- بيان العملية (شراء خامات، غداء، صيانة...)
    category TEXT,                                  -- تصنيف (شراء، صيانة، مواصلات، فواتير...)
    status TEXT NOT NULL DEFAULT 'completed',       -- 'completed' | 'pending_invoice'
    from_account TEXT,                              -- الحساب المسحوب منه (كاش، بنك، فيزا الشغل...)
    to_account TEXT,                                -- الحساب المحول إليه (في التحويلات)
    settlement_type TEXT NOT NULL DEFAULT 'none',   -- 'none' | 'claim_from_work' (لي عند الشغل) | 'owe_to_work' (عليّ للشغل)
    settlement_status TEXT NOT NULL DEFAULT 'none', -- 'none' | 'pending' | 'settled'
    receipt_path TEXT,                              -- مسار/رابط صورة الفاتورة عند استلامها
    area_id TEXT,                                   -- اختياري: لفرز المصروفات حسب المجال (عمل / شخصي)
    task_id TEXT,                                   -- اختياري: إذا أردت تذكر العملية مع مهمة معينة
    transaction_date TEXT NOT NULL,                 -- تاريخ المعاملة
    notes TEXT,                                     -- ملاحظات وتفاصيل
    sync_status TEXT NOT NULL DEFAULT 'pending_insert',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    deleted_at TEXT
);
`

## 4. تجربة المستخدم التفاعلية (UI/UX)

1. **القائمة الجانبية (Sidebar)**:
   - قسم **"السجل المالي والتسويات" (Financial Logs & Settlements)** مع شارة عداد الفواتير المعلقة.
2. **الشاشة المركزية للسجل المالي (FinancialLogScreen)**:
   - **رأس إحصائي مالي ذكي**:
     - 🟠 **فواتير معلقة**: عدد ومبلغ المشتريات التي لم تُستلم فواتيرها بعد.
     - 🟢 / 🔴 **صافي تسوية الشغل**: يوضح فوراً (ليك عند الشغل كام أو عليك للشغل كام).
   - **شريط فلاتر بنقرة واحدة**:
     - (الكل | ⚠️ بانتظار الفاتورة | 💼 مطلوب استرداده من الشغل | 🏠 مدفوع شخصي من الشغل | 🔄 تحويلات).
   - **نافذة الإضافة السريعة**:
     - تحديد المبلغ والبيان.
     - اختيار وسيلة الدفع (كاش، بنك، عهدة الشغل).
     - خيار سريـع بنقرة واحدة: هل دُفع للشغل من جيبي؟ أم دُفع شخصي من حساب الشغل؟
     - مربع اختيار: **"لم أستلم الفاتورة بعد"**.
3. **التصدير الفوري**:
   - زر تصدير كشف تسوية ومصروفات إلى Excel/CSV بترميز UTF-8 سليم.
